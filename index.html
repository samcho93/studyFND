    시작하기

    숫자 하나가 FND에 켜지기까지

    디지털 시계 속 숫자는 카운터(7490) → 디코더(7446) → FND 순서로 신호가 흘러가며 만들어집니다. 이 강좌에서는 각 칩이 하는 일을 Java 메서드 하나씩으로 만들고, 서로 연결해 0 ~ 9를 세는 카운터를 콘솔에 출력합니다. 마지막에는 카운터 두 개를 이어 시계의 기본인 100진·60진 카운터를 만듭니다.

    전체 흐름

    입력int 7
    →
    Step 1 · 6cnvtDec2Bin / ttl7490
    →
    4비트{1,1,1,0}
    →
    Step 2ttl7446
    →
    7비트{1,1,1,0,0,1,0}
    →
    Step 3makeFnd
    →
    콘솔char[5][5]

    하드웨어로 보면 이런 회로입니다. 오른쪽 FND는 Step 2의 결과인 7비트 값으로 그린 모양입니다.

    Step 1

    10진수를 4비트 배열로 바꾸기

    FND 회로의 모든 칩은 0과 1만 주고받습니다. 첫 단계에서는 10진수 하나를 받아 네 개의 비트를 배열에 담아 돌려주는 메서드를 만듭니다.

    • 나머지(%)와 몫(/)으로 2진수 구하기
    • 배열 인덱스와 비트 자리의 관계
    • 배열을 반환하는 메서드
    static int[] cnvtDec2Bin(int num)

    원리: 2로 나눈 나머지가 비트

    10진수를 2로 계속 나누면, 매번 나오는 나머지가 낮은 자리부터 차례로 2진수의 비트가 됩니다. 4비트면 네 번만 나누면 됩니다.

    직접 해보기num = 0 ~ 15
    결과 (MSB → LSB)
    반환 배열
    배열 순서에 주의하세요. out[0]에는 가장 낮은 자리(2⁰), out[3]에는 가장 높은 자리(2³)가 들어갑니다. 그래서 6(0110)을 배열 그대로 출력하면 {0,1,1,0}, 5(0101)는 {1,0,1,0}처럼 거꾸로 보입니다. 7490 칩의 출력 핀 QA~QD 순서와 같습니다.

    코드

    cnvtDec2BinBit은 같은 일을 비트 연산으로 합니다. num & 0x01은 맨 오른쪽 비트만 남기고, num >>= 1은 한 칸 오른쪽으로 밀어 다음 비트를 꺼낼 준비를 합니다. 결과는 두 메서드가 같습니다.

    확인 문제

    cnvtDec2Bin(9)가 반환하는 배열은?
    {1,0,0,1} — 9 = 8 + 1 이므로 out[0]과 out[3]이 1입니다.
    num에 16을 넣으면 어떻게 될까요?
    네 번만 나누므로 {0,0,0,0}이 됩니다. 5번째 비트(16의 자리)는 버려집니다. 4비트로 표현할 수 있는 범위는 0 ~ 15입니다.
    반복문 안에서 num = num / 2를 빼먹으면?
    num이 바뀌지 않아 네 칸 모두 같은 값(num % 2)이 들어갑니다. 예: 6 → {0,0,0,0}, 7 → {1,1,1,1}.

    연습 과제

    2. 반대로 4비트 배열을 받아 10진수를 돌려주는 int cnvtBin2Dec(int[] bin)을 만드세요. (Step 2에서 사용합니다)
    3. 비트 수를 매개변수로 받는 int[] cnvtDec2Bin(int num, int size)로 확장해 보세요.
    Step 2

    4비트를 FND 세그먼트 신호로 바꾸기

    FND는 막대 7개(a ~ g)의 LED로 숫자를 만듭니다. 4비트 값을 보고 어떤 막대를 켤지 정해 주는 칩이 BCD-7세그먼트 디코더 7446이고, 이번 단계에서 이 칩을 메서드로 만듭니다.

    • 세그먼트 a ~ g의 위치
    • 2차원 배열로 만든 진리표
    • 가중치 8·4·2·1로 인덱스 구하기
    static int[] ttl7446(int[] bin) // 반환: {a, b, c, d, e, f, g}

    세그먼트 이름과 진리표

    위에서부터 시계 방향으로 a, b, c, d, e, f, 가운데가 g입니다. 숫자 0 ~ 9마다 켜야 할 세그먼트를 표로 만들어 두고, 4비트 값을 10진수로 바꾼 뒤 그 행을 꺼내면 됩니다.

    직접 해보기비트를 눌러서 바꿔 보세요
    입력 bin (MSB → LSB)
    인덱스 계산 반환 배열 {a,b,c,d,e,f,g}
    실제 7446과의 차이. 실제 74LS46/47은 출력이 0일 때 세그먼트가 켜지는 Active-Low 칩(Common Anode FND용)입니다. 이 강좌에서는 이해하기 쉽도록 1 = 켜짐으로 통일했습니다. (Active-High인 7448과 같은 동작)

    코드

    참고 코드의 원래 버전은 return table[num];만 있어서 10 ~ 15가 들어오면 ArrayIndexOutOfBoundsException이 발생합니다. 여기서는 if (num > 9) return new int[7];로 모든 세그먼트를 끄도록 막았습니다. new int[7]은 0으로 채워진 배열입니다.

    확인 문제

    bin = {0,1,1,0} 일 때 num은?
    0×8 + 1×4 + 1×2 + 0×1 = 6 입니다. bin[3]이 MSB라는 점을 기억하세요.
    숫자 1에서 켜지는 세그먼트는?
    b, c — 오른쪽 세로 막대 두 개입니다. 표의 {0,1,1,0,0,0,0}.
    return table[num];이 반환하는 배열을 밖에서 바꾸면 어떤 일이 생길까요?
    table은 메서드가 호출될 때마다 새로 만들어지므로 다음 호출에는 영향이 없습니다. 하지만 table을 static 필드로 옮기면 원본 표가 바뀌는 버그가 생깁니다. 그럴 땐 table[num].clone()을 반환하세요.

    연습 과제

    1. 10 ~ 15일 때 16진수 A ~ F 모양이 나오도록 표를 16행으로 늘려 보세요. (A: a,b,c,e,f,g)
    2. Active-Low 버전 ttl7446Low(int[] bin)을 만들어 0과 1을 뒤집어 반환해 보세요.

    • 하강 엣지(1 → 0) 검출
    • 리셋 우선순위

    동작 규칙

    엣지는 어떻게 알 수 있을까?
    
  
    메서드는 호출되는 순간의 clk 값만 받습니다. "1에서 0으로 바뀌었다"를 알려면 직전 값이 필요하므로, 메서드 밖에 static int oldclk를 두고 매번 마지막에 현재 clk를 저장합니다. 지역 변수는 메서드가 끝나면 사라지기 때문에 쓸 수 없습니다.

    왜 b3일까?
    
  
    b3(가중치 8)는 8과 9일 때만 1입니다. 그래서 1 → 0으로 떨어지는 순간은 9 → 0으로 넘어갈 때 딱 한 번뿐입니다. 7490은 하강 엣지에서만 세므로, 7 → 8에서 b3가 0 → 1로 올라갈 때는 아무 일도 일어나지 않습니다.
    
  
    
  
    
    
    1의 자리 변화b3 b2 b1 b0b3 변화10의 자리
    
    
      
    6 → 70110 → 01110 → 0유지
    
      
    7 → 80111 → 10000 → 1 (상승)유지
    
      
    8 → 91000 → 10011 → 1유지
    
      
    9 → 01001 → 00001 → 0 (하강)+1

      •

    문제 3 · 1단계
    
  
    int 하나에 숫자 여덟 개
    
  
    int는 32비트입니다. 4비트씩 끊으면 니블(nibble) 8개가 되고, 니블 하나에 0 ~ 15를 담을 수 있습니다. 0 ~ 9만 쓰면 배열 없이 변수 하나에 숫자 8개를 넣을 수 있습니다. 다음 단계에서 이 상태 그대로 정렬합니다.
    
  
    • 니블 자리와 시프트 값
    • 꺼내기 = 밀기 + 마스크
    • 넣기 = 비우기 + 끼워넣기
    

  
    
    
    니블 지도왼쪽이 0번. s 는 그 니블이 시작하는 비트 위치
    
    
    
    
    
    
    k 번 니블은 s = (7 - k) * 4 번째 비트에서 시작합니다. 문제 1에서 7 - i로 인덱스를 뒤집던 것과 같은 계산입니다.
    
  
    

  
    쓸 연산은 다섯 가지뿐
    
  
    
  
    
    
    연산하는 일여기서 쓰는 곳
    
    
      
    & AND둘 다 1인 자리만 1필요한 비트만 남긴다 — x & 0xF
    
      
    | OR하나라도 1이면 1비운 자리에 값을 끼워 넣는다
    
      
    ~ NOT0과 1을 뒤집는다마스크를 뒤집어 지울 자리를 만든다
    
      
    << 왼쪽 시프트비트를 왼쪽으로 민다값을 제자리로 옮긴다 — d << s
    
      
    >> 오른쪽 시프트비트를 오른쪽으로 민다읽을 니블을 맨 아래로 내린다
    
      
    ^ XOR다르면 1두 번 하면 제자리 — 교환 기법에 쓰인다
    
        
  
    
  
    
  
    마스크(mask)란 "어느 자리를 건드릴지" 표시한 비트 묶음입니다. 0xF는 0000 1111, 즉 니블 하나를 덮는 마스크입니다. 0xF << s로 원하는 자리로 옮겨 쓰고, ~로 뒤집으면 그 자리만 지우는 마스크가 됩니다.
    

  
    
    
    그림으로 보기32비트를 4비트씩 끊어 보여 줍니다
    
    
    
    
    니블 번호 k
    
    
    넣을 값 d
    
    
    
    
    붉게 표시된 4비트가 지금 다루는 니블입니다. 꺼내기는 밀어서 맨 아래로 내린 뒤 & 0xF로 나머지를 잘라 내고, 넣기는 그 자리를 ~ 마스크로 비운 뒤 |로 끼워 넣습니다. 맨 위 니블이 8 이상이면 n이 음수라 >>가 위쪽을 1로 채우는데(두 번째 줄), & 0xF가 그 위를 모두 잘라 내므로 결과는 안전합니다.
    
  
    

  
    연산 확인 프로그램
    
  
    각 연산이 실제로 어떻게 동작하는지 2진수로 찍어 봅니다. 값을 바꿔 가며 실행해 보세요.
    
  
    

  
    확인 문제
    
  
    0xF << 12는 몇 번 니블을 덮을까요?
    s = 12이므로 (7 - k) * 4 = 12 → k = 4번 니블입니다. 2진수로는 0000 0000 0000 0000 1111 0000 0000 0000입니다.
    
  
    & 0xF를 빼고 n >> s만 하면?
    원하는 니블 위쪽 비트가 모두 따라옵니다. 0번 니블을 읽을 때는 문제가 없지만, 7번 니블을 읽으면 앞의 일곱 니블 값까지 섞여 큰 수가 나옵니다.
    
  
    값을 넣을 때 자리를 비우지 않고 n | (d << s)만 하면?
    원래 있던 비트가 남아 OR로 섞입니다. 예를 들어 5(0101)가 있는 자리에 2(0010)를 넣으면 7(0111)이 됩니다. 그래서 & ~(MASK << s)로 먼저 지워야 합니다.
    
  
    >>와 >>>의 차이는?
    >>는 부호 비트를 채우며 밀고(음수면 1이 들어옴), >>>는 항상 0을 채웁니다. 맨 위 니블이 8 이상이면 int가 음수가 되므로, & 0xF를 같이 쓰거나 >>>를 쓰면 안전합니다.

    씨앗값(seed). makeRandom(20260929)은 실행할 때마다 같은 숫자를 만듭니다. 결과를 비교하기 쉽도록 고정해 둔 것이고, 다른 값을 넣으면 다른 배치가 나옵니다. 진짜 무작위가 필요하면 (int)(Math.random() * 10)을 쓰면 됩니다.
    

  
    참고
    
  
    빈칸 ①
    return (n >> s) & MASK;

    s만큼 오른쪽으로 밀면 원하는 니블이 맨 아래로 내려옵니다. 그 위에 남아 있는 비트를 & MASK로 잘라 냅니다. 두 연산의 순서를 바꾸면 엉뚱한 값이 나옵니다.
    
  
    빈칸 ②
    return (n & ~(MASK << s)) | (d << s);

    왼쪽 괄호가 자리 비우기, 오른쪽이 값 끼워 넣기입니다. MASK << s는 그 자리만 1, ~를 붙이면 그 자리만 0이 되어 AND로 지워집니다.
    
  
    빈칸 ③
    int t = get(n, i);
    n = set(n, i, get(n, j));
    n = set(n, j, t);
    return n;

    먼저 꺼내 두지 않고 set부터 하면 값이 덮여 사라집니다. 문제 2에서 int t = a[i];로 자리를 바꾸던 것과 같은 이유입니다.

    비트만으로 하는 방법도 있습니다: int x = get(n,i) ^ get(n,j); 를 두 자리에 각각 XOR 하면 임시 변수 없이 교환됩니다.
    
  
    빈칸 ④
    if (get(n, k) > get(n, k + 1)) n = swap(n, k, k + 1);

    swap은 바뀐 n 을 돌려주는 메서드이므로 n = 으로 다시 받아야 합니다. 받지 않으면 아무 일도 일어나지 않습니다.

    씨앗값 20260929이면 처음이 8 0 0 3 6 5 1 5(0x80036515), 정렬 후가 0 0 1 3 5 5 6 8(0x00135568)입니다. 마지막 줄에 오름차순 정렬 완료가 나오면 성공입니다.
    

  
    확인 문제
    
  
    swap에서 set을 두 번 부를 때 순서를 바꾸면?
    임시 변수에 먼저 담아 두었다면 순서를 바꿔도 결과는 같습니다. 담아 두지 않고 set(n, i, get(n, j)) → set(n, j, get(n, i))로 하면, 두 번째 get이 이미 바뀐 값을 읽어 두 자리가 같은 값이 됩니다.
    
  
    맨 왼쪽 니블이 8이나 9이면 n이 음수가 됩니다. 문제가 될까요?
    출력이 음수로 보일 뿐, 비트는 그대로입니다. 다만 n >> s는 부호 비트를 채우며 밀기 때문에 위쪽이 1로 덮입니다. & MASK가 그 위를 잘라 주므로 안전하고, >>>를 써도 됩니다.
    
  
    니블에 10 ~ 15가 들어 있어도 정렬될까요?
    됩니다. 니블은 0 ~ 15를 담을 수 있고 비교도 그대로 동작합니다. 0 ~ 9로 제한한 것은 16진수로 찍었을 때 사람이 읽기 쉽게 하려는 것뿐입니다.
